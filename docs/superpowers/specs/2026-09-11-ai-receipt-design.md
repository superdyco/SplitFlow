# AI 辨識收據（第一階段）

## 為什麼要做

出國記帳最麻煩的不是打金額，是外文收據：日文、泰文的店名看不懂，也不確定上面寫的
是哪一種幣別。拍張收據就把金額、幣別、日期、時間、店名、分類填好，是這個 App 最
直接能省下力氣的地方。

收據拍照早就有了（`docs/superpowers/specs/2026-08-04-expense-receipt-photo-design.md`），
todo 上寫著「純憑證用途，沒有 OCR」。這份 spec 把辨識接在那條現成的流程上。

## 範圍

**第一階段（這份）**：AI 辨識＋一次性的免費點數＋後台維護金鑰、調整點數、看使用報告。

**第二階段（另寫 spec）**：購買點數。**只在 App 內購買**（Apple／Google 的應用程式內
購買），**網頁版永遠不賣**。點數存在伺服器、跟著帳號走，所以 App 買的點數在網頁上
辨識一樣扣得到。這份 spec 的點數紀錄已經預留了「購買」這種類型的位置。

## 已確認的決定

| 題目 | 決定 |
|---|---|
| 誰能用 | 任務裡每一個成員；點數扣按下辨識的那個人的 |
| 訪客 | 看得到按鈕，按下去提示綁定帳號；不送點數 |
| 付費方式 | 點數，不讓使用者綁自己的 AI 金鑰 |
| 免費點數 | **每個帳號一次 3 點，用完就沒了**，不會每月補 |
| 扣點時機 | **每次呼叫 AI 就扣 1 點**，不管讀不讀得出來。沒有退點、沒有每日上限 |
| 失敗怎麼辦 | 後台記下每一次的結果（成功或哪種失敗）。使用者申訴時，管理者照紀錄**手動調整點數** |
| 自訂分帳遇上 AI 改金額 | **切回平分** |
| 管理者先調了還沒用過的人 | **管理者輸入幾點就是幾點**，之後不再送免費 3 點 |
| 收據幣別不在支援清單 | **幣別改用任務的主要幣別** |
| AI 填哪些欄位 | 金額、幣別、日期、時間、店名（填進支出名稱）、分類 |
| 已經有值的欄位 | **全部蓋掉**（使用者的決定），並顯示「AI 已填入：…」 |
| 照片怎麼送 | 存檔前直接送給雲端函式，不先上傳 Storage |
| AI 服務 | **OpenAI（ChatGPT）**，不用 Claude |
| 金鑰 | 在管理後台維護，不用 Firebase secret |
| 後台 | 能換金鑰與模型、能調整使用者點數（加或減）、有使用報告 |

## 1. 點數的資料與規則

### 存在哪裡

| 路徑 | 內容 | rules |
|---|---|---|
| `aiCredits/{uid}` | `balance`（整數，不會小於 0）、`freeGranted`（是否已送過免費點數）、`updatedAt` | 本人只能讀，任何人都不能寫 |
| `aiCredits/{uid}/aiLedger/{id}` | 每一次點數變動一筆（見下） | 本人只能讀，任何人都不能寫 |

**不放在 `users/{uid}`**：那份文件的 `create` 規則沒有限制欄位，使用者在取暱稱那一步
就能寫進 `aiCredits: 9999`。放在獨立的集合、rules 全擋寫入，才只有雲端函式能動點數。

子集合取名 `aiLedger` 而不是 `ledger`：後台要用 collection group 跨使用者查，名字要
獨一無二，不能跟其他地方的子集合撞名。

### 點數紀錄（`aiLedger`）

每一次點數變動都是一筆，**報告從這裡產生，餘額可以用它對帳**。

| 欄位 | 說明 |
|---|---|
| `type` | `free`（送免費點數）、`use`（辨識扣點）、`adjust`（管理者調整）。第二階段加 `purchase`。 |
| `delta` | 變動量：+3、−1、±n |
| `balanceAfter` | 變動後的餘額 |
| `at` | 伺服器時間 |
| `uid` | 點數的主人（collection group 查詢時要知道是誰的，不能只靠路徑） |
| `readResult` | 只有 `use`：扣點當下先寫 `pending`，AI 回來後改成 `read`（讀出金額）或失敗原因（`unreadable`、`not_receipt`、`ai_error`、`timeout`）。**一直停在 `pending` 就是函式中途當掉** —— 扣了點卻沒有結果，申訴時一眼看得出來 |
| `model`、`inputTokens`、`outputTokens` | 只有 `use`，AI 回來後跟 `readResult` 一起補上：用了哪個模型、多少 token。算真實成本用。 |
| `adminUid`、`adminEmail`、`reason` | 只有 `adjust`：誰調的、為什麼 |

### 免費 3 點

不預先發放。**正式帳號第一次用辨識時**，函式發現 `aiCredits/{uid}` 不存在，就建立它、
`balance: 3`、`freeGranted: true`，並寫一筆 `free`。

- 訪客不能用，所以不會拿到。綁定帳號之後 uid 不變，第一次用時才拿到 3 點。
- 訪客合併進既有帳號（`mergeGuest`）：訪客從來沒有點數，不必處理。
- 管理者先幫還沒用過的人調整點數：`adminAdjustCredits` 建立文件，`balance` 就是
  管理者輸入的數量（負數當作 0），`freeGranted: true`，只寫一筆 `adjust`、不寫 `free`。
  之後第一次用辨識時文件已經存在，**不會再加 3 點** —— 管理者輸入幾點就是幾點。
- 同一個人刪帳號後重新註冊：Firebase 會給新的 uid，會再拿到 3 點。接受這個漏洞 ——
  損失上限是 3 張收據的費用。

### 扣點

**規則只有一條：呼叫 AI 就扣 1 點。** 不退點、沒有每日上限、沒有自動補償。
讀不出來、不是收據、AI 出錯、逾時，一律照扣，結果全部記在點數紀錄裡。使用者覺得
不合理來申訴，管理者看紀錄，用「調整點數」手動補回去。

1. **扣點**（transaction）：讀 `aiCredits/{uid}`，餘額大於 0 就 −1，並寫一筆 `use`
   （`readResult: "pending"`）；等於 0 就拒絕。只剩 1 點時同時按兩次，第二次在
   transaction 裡就會看到 0。
2. 呼叫 AI。
3. 把第 1 步那一筆 `use` 補上 `readResult`、`model`、token。

呼叫 AI **之前**就被擋下的（沒登入、訪客、照片不合格、還沒設定金鑰、餘額 0）不扣點
—— 那些根本沒花到錢。

每個帳號只有 3 點，被刷也刷不出 3 張以上的費用，所以不需要每日上限。第二階段開放
購買之後，買來的點數本來就是使用者自己付的錢，照扣也合理。

### 刪除帳號

`deleteAccount` 一併刪掉 `aiCredits/{uid}` 與它的 `aiLedger`。點數紀錄是這個人的資料，
跟收藏、推播 token 同一類。

## 2. 雲端函式 `readReceipt`

### 設定：`config/ai`

| 欄位 | 說明 |
|---|---|
| `apiKey` | OpenAI 的 API 金鑰。**完整值只有雲端函式讀得到** |
| `model` | 模型名稱，**只能是程式裡白名單上的一個**（見下）。預設 `gpt-5.6-luna` |
| `keyTail` | 金鑰末四碼，給後台顯示用 |
| `updatedAt`、`updatedBy` | 最後一次由誰在什麼時候更新 |

rules：`allow read, write: if false`。後台讀寫都走 callable（Admin SDK 繞過規則）。

### 模型白名單

照 Codex 的做法：OpenAI 的模型清單 API 只回名稱，**不說哪個模型能看圖**，所以能力
要寫在自己的程式裡。`functions/` 裡放一份白名單，只收**能讀圖片、支援結構化輸出**的
模型，每個附上顯示名稱：

| 模型 | 說明 |
|---|---|
| `gpt-5.6-luna` | **預設**。最便宜（輸入每百萬 token $0.20）。第三方評測 OCR 88.4%，跟 Terra 只差 0.4 |
| `gpt-5.6-terra` | Luna 讀不準時的備案，貴 10 倍 |
| `gpt-5.6-sol` | 最準（OCR 90.7%），再貴 2.5 倍 |

後台只能從這張表挑，**不能自由輸入**。新模型出來要改白名單、重新部署 —— 換到的是
「不可能選到不能看圖的模型」。在白名單裡切換則不用部署。

Luna 夠不夠準，評測數字只能參考（不是專門測收據，也沒測日文、泰文）；上線前的手動
測試兩個模型都要跑（見第 5 節），再決定預設留哪個。

### 設定的快取

函式讀設定時在同一個 instance 裡快取 60 秒，免得每張收據都多一次 Firestore 讀取；
後台換了金鑰，最慢一分鐘生效。

### 輸入與檢查

- 必須登入，而且**不能是匿名帳號**（`sign_in_provider === "anonymous"`）→
  `failed-precondition`「綁定帳號就能用 AI 辨識」。
- `image`：base64 的 JPEG。解碼後**最多 2 MB**（跟收據上傳的 `MAX_UPLOAD_BYTES` 一樣），
  而且檔頭要是 `FF D8`。兩個平台壓縮後都是長邊 1600px、約 200–400 KB，放得進一次呼叫。
- `config/ai` 沒有金鑰 → `failed-precondition`「AI 辨識還沒有設定好」，**不扣點**。
- 餘額 0 → `resource-exhausted`「AI 辨識點數用完了」。

這些訊息都是中文，照 2026-09-11 上線的錯誤訊息規則，兩個平台會原樣顯示。

### 呼叫 OpenAI

- 用 OpenAI 官方的 Node SDK。
- 用它的**結構化輸出**（JSON schema）把回傳固定成下面這六個欄位，每一個都可以是 null。
- 指令要點：
  - 金額是**最後實付的總額**（含稅、服務費、小費），不是小計。
  - 幣別回 ISO 4217 代碼。收據上沒寫明時，從符號、語言、店家所在國家推斷；不確定就回 null。
  - 日期 `YYYY-MM-DD`、時間 `HH:MM`（24 小時制），讀不到就回 null。
  - 店名照收據上印的寫，不翻譯。
  - 分類從 `food`、`transport`、`stay`、`ticket`、`shopping`、`other` 挑最接近的一個。
- 逾時 30 秒。

**API 的實際形狀、每張收據的確切成本，不在這份 spec 決定**：寫實作計畫時對照
OpenAI 官方文件與價格頁確認，並把估算寫進計畫。粗估用 Luna 每張遠低於 0.1 美分，
用 Sol 也在 1 美分上下。每個帳號只有 3 點，所以第一階段的總成本上限是「帳號數 × 3 張」。

**用的是 API 金鑰，不是 ChatGPT 訂閱**：ChatGPT／Codex 月租的額度只給訂閱者本人用，
不能拿來服務 App 的使用者；API 在 platform.openai.com 另外儲值、照用量計費。

### 回來的內容一律再檢查一次（純函式，有測試）

| 欄位 | 合格條件 | 不合格時 |
|---|---|---|
| 金額 | 大於 0 的數字 | **算沒讀出來**（`unreadable`），點數照扣 |
| 幣別 | 三個大寫字母 | 當作 null |
| 日期 | `YYYY-MM-DD` 而且是真的日期 | 當作 null |
| 時間 | `HH:MM`，00:00–23:59 | 當作 null |
| 店名 | 去掉頭尾空白，最多 60 字（支出名稱的上限） | 超過就截短；空的當作 null |
| 分類 | 六類之一 | 當作 null |

**金額照幣別整理小數位**：幣別在支援清單裡時，用 `functions/src/amount.ts` 的
`minorUnits` 四捨五入到該幣別的位數，回傳成表單直接能用的字串（日圓 `1280`、美元
`12.50`）。這是推播通知在用的同一份規則，表單拿到的格式一定合法。

### 回傳

```
{
  readResult: "read" | "unreadable" | "not_receipt",
  fields: { amount, currency, currencySupported, date, time, title, category },
  creditsLeft: number
}
```

`readResult` 不是 `read` 的時候 `fields` 可能全是 null。其他有讀到的欄位照樣填入，
畫面顯示「沒有讀出金額（已扣 1 點），其他有讀到的欄位已填入」（一個都沒讀到時只顯示
「沒有讀出金額（已扣 1 點）」）。

`currencySupported` 是這個幣別在不在 20 種裡；不在的話 `amount` 照收據上的數字回傳，
由畫面決定怎麼提示。

### 失敗

AI 服務出錯或逾時 → 點數照扣，紀錄寫 `ai_error`／`timeout` → `unavailable`
「AI 辨識暫時無法使用。」

### 其他

- `maxInstances` 設上限，避免被刷的時候費用失控；最後一道防線是 OpenAI 那邊的用量上限。
- 每次辨識都更新 `stats/ai/days/{YYYY-MM-DD}`（`calls`、`reads`、`failures`、`inputTokens`、
  `outputTokens`，用 `FieldValue.increment`），給後台的用量摘要用。做法跟訪客統計
  （`stats/guests/days`）一樣，不放進每日彙總那份會被整份覆寫的文件。

## 3. 兩個平台的畫面

### 按鈕在哪裡出現

支出表單裡，**剛拍或剛選了一張照片**時，收據旁邊出現「用 AI 讀收據（剩 N 點）」。

- 網頁：壓縮後的照片在 `useReceipt` 的 `pending`（Blob），現在沒有公開，要多回傳它。
- Flutter：`ReceiptField` 已經把壓縮好的 `File` 透過 `onChanged` 交給表單（`_receipt.file`）。
- 編輯既有支出時，已經存好的收據**不出現**按鈕 —— 照片在雲端，不在這台裝置上。要辨識
  就重新拍一張。

### 按鈕的狀態

| 狀態 | 顯示 |
|---|---|
| 正常 | 「用 AI 讀收據（剩 N 點）」；還沒用過的正式帳號顯示 3 點 |
| 訪客 | 按鈕照樣顯示；按下去提示「綁定帳號就能用 AI 辨識」並給一個到個人頁的連結 |
| 點數用完 | 停用，「AI 點數用完了」 |
| 沒網路 | 停用，「需要網路」 |
| 辨識中 | 「辨識中…」，表單其他地方照常能編輯 |

餘額從 `aiCredits/{uid}` 讀（本人讀得到）；文件不存在就當作 3。

### 讀到之後

- 讀到的欄位**全部蓋掉**：金額、幣別、日期、時間、支出名稱、分類。沒讀到的欄位不動。
- 收據旁邊顯示一行「AI 已填入：金額、幣別、日期…（剩 N 點）」—— 編輯既有支出時，
  這是唯一讓人注意到哪些欄位被改掉的地方。
- **幣別跟主要幣別不同時自動查匯率**：網頁的 `watch(currency)` 本來就會做；Flutter
  現在只有按鈕觸發 `_lookupRate`，AI 填入幣別後要主動呼叫一次。Flutter 的換幣別邏輯
  （`_rateUpdatedAt` 清空、同幣別時匯率設 1）抽成一個方法，選單與 AI 共用。
- **分帳是自訂金額、而且 AI 改了金額或幣別時，切回平分**。分攤的人維持原本那幾位
  （自訂金額大於 0 的成員），清掉各人的自訂金額，並在「AI 已填入」那一行加上
  「分帳已改回平分」。不切的話各人金額加總對不上新的總額，儲存按不下去，使用者也
  看不出原因。金額跟幣別都沒變時不動分帳。
- 幣別不在支援的 20 種裡：**幣別欄改成任務的主要幣別**（匯率跟著變 1），金額照收據
  上的數字填入，再依主要幣別的小數位四捨五入（函式不知道任務的主要幣別，這一步在
  畫面做）。提示用警告樣式、不會自己消失：「收據上是 XXX 40,000，目前不支援這個
  幣別，已改用 TWD —— 金額請自己換算後再存」。幣別因此變了的話，上面「切回平分」
  那條照樣適用。
- 失敗：顯示函式回來的中文訊息，並更新剩餘點數（AI 出錯也已經扣了 1 點）。

### 地點候選（2026-09-13 追加）

原本這份 spec 把地點列在「這次不做」，理由是店名不等於 Places 上的地點、搜尋會錯。
改成**列候選、使用者點了才填**，那個風險就留在使用者手上，而不是由程式替他猜。

- AI 多讀一個 `address`：收據上印的店家地址，照印的寫、不翻譯，沒印就是 null
  （不從店名推測）。它**不是表單欄位**，只用來搜尋。
- AI 讀完、而且讀到店名或地址時，用「店名 地址」呼叫現有的 Places autocomplete，
  位置偏好跟地點欄位一樣（這個任務上次選的地點），列出**最多 3 家**：「是不是這家？」
- **點了才填進地點**，不自動選第一個 —— 連鎖店同一個名字附近有好幾家，選錯的
  地點會出現在公開報告的地圖上，而使用者不一定會發現。
- 候選都不對可以按「都不是」收起來；查不到或沒有地點金鑰就整塊不出現。
- 費用：只在 AI 讀完之後查一次 autocomplete，選了才多一次 details，兩者共用
  session token 算一次計費。
- 地點欄位的初始值只讀一次（避免打字時跟母元件互相觸發），所以選了候選之後要換
  key 讓它用新的地點重建。

### 個人頁

兩個平台都加一行「AI 辨識點數：N」。

## 4. 後台

### 新增一頁「AI 設定」（`/admin/ai`，排在「系統健康」後面）

- **金鑰狀態**：尚未設定，或「末四碼 ••••abcd，最後由 xxx 於 yyyy-mm-dd 更新」。
- **模型**：下拉選單，選項就是白名單（第 2 節），顯示名稱＋一句說明。
- **更換金鑰或模型**：金鑰是密碼格式的輸入框（只換模型時可以留空，沿用舊金鑰）＋
  必填理由。**存之前先用 OpenAI 的「查詢單一模型」API 驗一次，驗不過就不存** ——
  金鑰錯、被撤銷、這把金鑰用不了那個模型，都會在這一步失敗，而且這個查詢不花錢。
  貼錯一個字就讓全站辨識停擺，是最容易發生的事故。
- **「測試目前的設定」按鈕**：用程式裡內建的一張小樣本收據，**實際跑一次辨識**，
  顯示讀到的欄位、token 與耗時。只有真的呼叫才抓得到「帳戶沒錢」—— 上面那個
  查詢抓不到。每按一次花一點點錢（Luna 不到 0.1 美分），只有管理者手動按才會跑，
  不扣任何人的點數、不寫 `aiLedger`。
- **用量摘要**：讀 `stats/ai/days`，照總覽的區間（7／30／90 天、算到今天）顯示辨識
  次數、讀出次數、失敗次數、token 合計。
- **使用報告**：跨所有使用者的點數紀錄（collection group `aiLedger`），由新到舊、
  分頁，可以只看某一種類型（扣點／調整／免費）。每一列：時間、使用者暱稱、
  類型、變動、變動後餘額、結果（辨識才有；`pending` 超過一分鐘顯示「沒有回來」）、
  token（辨識才有）、理由（調整才有）。

callable：`adminAiConfig`（讀狀態，不含完整金鑰）、`adminSetAiConfig`（更換，
先測再存）、`adminTestAiConfig`、`adminAiUsage`（摘要＋報告分頁）。

### 使用者詳情

- 「AI 點數：N」。
- **「調整點數」**（2026-09-13 改）：**直接輸入要設成幾點**（0 到 1000），不是加減量 ——
  管理者要的是「他現在該有幾點」，自己算加減容易算錯。＋必填理由。紀錄照樣寫實際變動量
  （例如餘額 2、設成 5，紀錄寫 +3）。跟現在一樣就擋下來，不寫一筆變動 0 的紀錄；還沒用過
  的人設成 0 例外（照樣建立，等於不送免費 3 點）。**訪客不能調整** —— 訪客本來就不能用，
  調了只會讓人以為壞了。寫一筆 `adjust` 到 `aiLedger`。
- **「辨識 N 次，失敗 M 次」**：從這個人的 `aiLedger` 算，申訴時一眼看出他說的是不是真的。
- 這個人自己的點數紀錄（同一份 `aiLedger`，只看他的），每筆辨識都看得到結果。
  **預設只列最近 5 筆**，要看再展開（最多到伺服器回的 20 筆）—— 紀錄一多，詳情會長到
  看不到下面的東西。

callable：`adminAdjustCredits`。

### 稽核日誌

- 新動作：`act.setAiConfig`（更換 AI 設定）、`act.adjustCredits`（調整點數），
  都在 `ACT_ACTIONS`，**都必須填理由**。
- `TargetType` 多一種 `config`。
- 稽核日誌頁補上這兩個動作的中文名稱。
- 看 AI 設定頁（含使用報告）屬於檢視：`VIEW_ACTIONS` 加一個 `view.ai`，每次打開那一頁記一筆，跟 `view.user` 同樣不需要理由。

### 索引

- collection group `aiLedger` 依 `at` 由新到舊：要在 `firestore.indexes.json` 加
  collection group 範圍的單欄位索引。
- 依 `type` 篩選再依 `at` 排序：一個 collection group 的複合索引。
- 使用者詳情只看一個人的：直接查 `aiCredits/{uid}/aiLedger`，不需要額外索引。

## 5. 隱私政策、這次不做的事、測試、上線前

### 隱私政策（`public/privacy.html`）

- 「一、我們收集的資料」表格加一列**收據照片**：你為支出附上的收據照片，存放在
  Firebase Storage（這件事從 2026-08-04 就在做了，表格一直漏寫）。
- 「四、我們使用的第三方服務」加一條 **OpenAI**：只在你按下「用 AI 讀收據」時，那張
  收據照片會傳送給 OpenAI 辨識；我們不會送出其他資料。附上 OpenAI 隱私政策的連結。

隱私政策另外還有幾處過時（Facebook 登入早就關了、沒寫 Apple 登入、沒寫 Open-Meteo
天氣、沒寫免登入試用），**不在這份 spec**，記進 todo 另外處理。

### 這次不做

- 購買點數（第二階段）。
- 逐項分帳（把收據上每一項分給不同人）。
- 辨識已經存好、在雲端的收據。
- 辨識完自動存檔 —— 一律是預填，使用者看過才按儲存。
- 每月補點數。

### 測試

- **純函式（functions，vitest）**：
  - 回傳內容的檢查與整理（上面那張表的每一條，含金額小數位）
  - 扣點的判斷（餘額 0、1、文件不存在、訪客）；呼叫 AI 前被擋下的不扣
  - 失敗照扣：`unreadable`、`not_receipt`、`ai_error`、`timeout` 都是 −1，紀錄的
    `readResult` 從 `pending` 補成對的值
  - 調整點數的判斷（設成幾點就是幾點、範圍 0 到 1000、紀錄寫實際變動量、跟現在一樣要擋、
    訪客拒絕；文件不存在時照樣建立、`freeGranted: true`，之後第一次辨識不再送 3 點）
  - 點數紀錄的組裝（三種類型的欄位）
  - 金鑰末四碼
  - 模型白名單：不在表上的名稱被 `adminSetAiConfig` 拒絕；`config/ai` 裡的名稱不在表上
    （例如白名單改過）時，`readReceipt` 退回預設模型
- **rules（emulator，JDK 21）**：
  - `aiCredits`、`aiLedger`：本人讀得到、別人讀不到、誰都寫不進去
  - `config/ai`：誰都讀不到、寫不進去
  - `users/{uid}` 建立時多帶 `aiCredits` 也不會變成點數（點數本來就不在那裡，這條是防回歸）
- **網頁（vitest）**：按鈕狀態的判斷（餘額、訪客、離線）抽成純函式；
  「AI 填入後分帳要不要切回平分、平分給誰」也抽成純函式（自訂＋金額變、
  自訂＋幣別變、自訂但都沒變、本來就是平分）；不支援的幣別改用主要幣別、金額依
  主要幣別小數位整理（例如 12.5 進 JPY 變 13）。
- **Flutter**：同兩組判斷的 Dart 版，靠 CI 驗。
- **手動**：設好金鑰後，實際拍一張日文、一張泰文、一張拍糊的收據，確認讀出、提示、
  扣點都對（拍糊的那張也扣 1 點）；後台看得到那幾筆的結果，手動補點數也正常。
- **模型比較（手動）**：同一批收據（至少日文、泰文各兩三張，含皺掉的熱感應紙）用
  Luna 與 Terra 各跑一次，比對金額、幣別、日期有沒有讀對。Luna 明顯較差才把預設
  換成 Terra。結果記在實作計畫裡。

### 上線前要你手動做的

- 申請 OpenAI 帳號、儲值、產生一把 API 金鑰，並在 OpenAI 那邊設**用量上限**。
- 部署 functions、rules、indexes、網頁。
- 到後台「AI 設定」貼上金鑰、選模型（先用 Luna）、按測試。
- App 要重新 build 才看得到按鈕。
