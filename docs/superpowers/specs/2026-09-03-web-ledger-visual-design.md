# 網頁版視覺改版：財務儀表 Design

**日期：** 2026-09-03
**範圍：** `src/` 全部十二頁與共用元件。`flutter_app/` 不碰。

## 1. 要解決的問題

現在的視覺系統是**對的**但**沒有立場**。前兩輪把該算的都算了 —— 對比度過 AA、圓角四階、陰影四階、橘色按「上面有沒有字」拆成兩支。這些都留著。

問題在於它對「這個 app 是什麼」沒有意見：

- 每一則內容都是一張浮起來的卡，所以沒有任何一則比較重要
- 金額跟旁邊的說明文字一樣大，而且不對齊
- 數字用比例字型，`1,250` 跟 `6,530` 的位數對不齊
- 密度平均，一屏看得到的東西比實際需要的少

而這個 app 每天真正被用到的動作只有兩個：**記一筆**，跟**我還欠誰多少**。兩件事都是看數字。

「財務儀表」這個方向的主張就是這一句：**數字優先，其餘讓路。**

已在設計稿確認：<https://claude.ai/code/artifact/bd80467a-8997-4540-aeab-d6cd0799b14b>（第一頁四張是採用的方向，第二頁是沒選上的兩個，留著備查）。

## 2. Token 層的變更（`src/assets/styles.css` 的 `:root`）

這一層改完，全站十二頁自動受惠一半。

### 2.1 圓角整條下移一階

```
--radius-sm: 10px → 6px    /* chip、seg-item、小標籤 */
--radius-md: 14px → 8px    /* .btn、.input、.select */
--radius-lg: 18px → 10px   /* .card */
--radius-xl: 22px → 14px   /* 對話框、底部彈出 */
--radius-pill: 999px       /* 不變 */
```

**只改值，不改名，不改使用點。** 四階仍然是四階，沒有 token 變成孤兒 —— 上一輪「定義了卻沒用的三個」那份稽核不要再發生一次。

為什麼是下移而不是重新分配：18px 的卡片圓角在密度提高之後會顯得鬆垮，而圓角本身不是這個方向要表達的東西。

**與設計稿的一處刻意差異：** 稿上的主要按鈕畫的是 10px（跟卡片同一階），這裡定的是 `--radius-md` 的 8px。在 44px 高的元件上兩者看起來一樣，而 8px 讓「元件越小、圓角越小」這條規則在整個 scale 上維持成立。按鈕**不換 token**，仍然用 `--radius-md`。

### 2.2 新增兩個顏色

```
--color-row-head: #faf8f5;  /* 列表表頭條。比 --color-card 深、比 --color-bg 淺 */
--color-row-line: #ece6de;  /* 列表內的分隔線 */
```

`--color-row-line` 比既有的 `--color-line` (#ede7e0) 再深一點點，因為它現在要承擔原本靠陰影在做的分隔工作 —— 卡片不再一張張浮起來，分隔就只剩這條線。

`--color-row-head` 上面會印 13px 的標題文字，**必須算過對比度**（見 §5）。

### 2.3 新增一個 utility：等寬數字

```css
.num {
  font-variant-numeric: tabular-nums;
  letter-spacing: -0.01em;
}
```

這是整個方向最核心的一條，而它既不是顏色也不是間距，是字體特性。金額要靠右對齊成一欄，用比例數字的話每一列的位數會錯開，對齊就是假的。

**規則：畫面上每一個金額都要有 `.num`。** 沒有例外。

### 2.4 字級不動

B 用到的 12 / 14 / 15 / 17 已經全部在既有的 scale 裡（`--text-tiny` / `--text-body` / `--text-control` / `--text-card`）。不加也不減。

## 3. 元件層的規則

### 3.1 `.card` 的角色改變

從「每一則內容一張卡」變成「**一組內容一個容器**」。

三張任務卡並排 → 一張卡，裡面三列，列與列之間一條線。這是密度提高的主要來源，也是「分隔線取代陰影」的具體長相。

新增兩個 class：

```css
.card-strip   /* 卡頂的表頭條：--color-row-head 底、13px/600、左標題右總計 */
.row-line     /* 列與列之間的 1px --color-row-line */
```

`.row-line` 的左邊要縮排到內容起點（有圖示欄的縮到圖示右緣，沒有的縮到 padding）。整條拉滿會讓列表看起來像表格而不是清單。

### 3.2 `.tabs` 廢除，統一用 `.seg`

專案現在同時有兩種切換器：`TaskPage` 的主層級用 `.tabs`（底線式），支出的清單/地圖用 `.seg`（分段控制）。兩者做同一件事卻長得不一樣，只能靠位置分辨層級。

B 統一成 `.seg`。**`.tabs` 與 `.tab` 改完之後是死 class，要刪掉** —— 這個 repo 不留沒人用的樣式。

### 3.3 `.btn` 的最小高度 48px → 44px

44 是 iOS 的建議下限，也過得了 WCAG 2.5.8 的 24×24。48 在密度提高之後顯得笨重。

**這是全站每一顆按鈕**，走查時要專門確認一輪沒有變得難按 —— 特別是並排的兩顆小按鈕。

### 3.4 金額排版的硬規則

1. 一律 `.num`
2. 在列表列裡靠右，**固定欄寬**（不是 `flex-grow`，欄寬固定才對得齊）
3. 主要金額 `--text-control` (15px) / 600 字重
4. 次要金額 `--text-tiny` (12px) / `--color-muted`
5. **在列表列裡，幣別代碼不跟金額同字級** —— 12px `--color-muted`，或放進標籤裡

第 5 條是因為一整欄的 `TWD 12,480` 同字級的話，眼睛每一列都要先跳過三個字母才讀得到數字。

**這條只管列表列。** 頁面上唯一的主數字（總花費、我的分攤、每人平均）維持 `TWD 12,480` 連寫 —— 那裡只有一個數字，沒有要對齊的對象，拆開反而讓它看起來不像一個完整的金額。設計稿就是這樣畫的。

## 5. 對比度：沿用既有的硬規則

- 文字一律 `--color-muted` (4.9:1) 以上
- **`--color-soft` (3.4:1) 不能印文字**，只能當非文字 UI
- 白字只印在 `--color-primary-dark` 以上

新增的 `--color-row-head` (#faf8f5) 上面會有 13px 標題，要算 `--color-ink` 與 `--color-muted` 對它的比值並記在註解裡。#faf8f5 幾乎是白的，預期會過，但**要算過才寫**。

## 6. 測試策略（誠實版）

**這一輪幾乎沒有可自動化測試的東西。** 版面、密度、對齊、圓角，測試套件一個都看不到 —— 跟 `2026-09-02-web-visual-system` 那輪一樣。

能靠的只有：

- `npm run check`（`vue-tsc --noEmit` + 既有測試）必須維持全綠
- `npm run build` 必須過
- 掃描：改完之後 `.tabs`/`.tab` 搜不到殘留；每個金額都有 `.num`
- **人工走查**，逐頁

**不要用「測試全綠」當作版面改對了的證據。** 這句話上一輪就寫在計畫裡，這輪一樣成立。

## 7. 不做的事

- **不動任何計算、資料流、路由、Firestore 規則。** 純視覺。
- **不動文案。** 一個字都不改。
- **不動 `flutter_app/`。** 它上一輪才對齊到現在的 token，這輪之後會再次落後 —— 那是另一輪的事，要另立 spec。這是這次改版已知且接受的代價。
- **不加深色模式。** 現在沒有，這輪也不加。
- **不動 `SettlementPanel` 的付款流程。**

## 8. 風險與分層

最大的風險是**一次改十二頁加全域 token，壞掉之後很難二分**。

所以實作要嚴格分層，每層獨立 commit、獨立可驗證：

1. **Token 層** —— `:root` 的圓角與兩個新顏色、`.num` utility。改完全站自動變化，這一步就要目視確認沒有東西爆版。
2. **共用元件層** —— `.card-strip`、`.row-line`、`.seg` 統一、`.btn` 高度、刪 `.tabs`。
3. **逐頁** —— 四頁有稿的先做（風險已知），八頁後做。

順序刻意讓風險最高的（全域 token）排第一：它如果錯了，第一步就會發現，而不是改到第九頁才發現每一頁都要重來。

## 9. 驗收

- `npm run check` 與 `npm run build` 全綠
- `.tabs` / `.tab` 全專案搜不到
- 每一頁人工走查一次，重點在：金額是否對齊成一欄、44px 按鈕是否還好按、分隔線是否取代了陰影而不是疊加
- 手機寬度（390px）與桌機（520px shell）各走一次
