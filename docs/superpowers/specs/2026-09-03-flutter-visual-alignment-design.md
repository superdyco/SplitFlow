# Flutter 視覺對齊與支出表單重排：token 補課、三張卡、固定送出列

日期：2026-09-03

## 目標

`lib/ui/theme.dart` 的第一行就寫著這件事該怎麼判斷：

> 兩個版本讀寫同一批資料、給同一群人用，看起來就該是同一個產品。
> 顏色直接照抄，不重新調 —— 「差不多的橘色」比明顯不同更糟。

它照抄的是 2026-09-02 **改版前**的 `:root`。而網頁版這兩輪動的正是 token 那一層，
所以現在兩邊不是「差不多」，是各自停在不同的版本。

但最要緊的一條不是好不好看：

**`bodySmall` —— 全 app 次要文字的預設 —— 用的 `muted` 是 `#8A8078`，
對頁面底色只有 3.4:1，過不了 WCAG 文字的 4.5:1。**

網頁版那一輪把整條灰階往下移一階就是為了修這個。Flutter 現在用的 `#8A8078`
正是網頁版移完之後**退居非文字用途**的那一階。日期、成員數、每人金額、
所有的提示與錯誤說明都印在這個顏色上。

第二件事：`expense_form_page.dart`（947 行，全專案最大）跟網頁版改版前**同構** ——
`SingleChildScrollView + Column`，十一個 `_Field` 平鋪，送出鈕在捲動流的最底。
網頁版昨天才把這一頁改成三張卡加固定送出列，理由在手機上只會更強：
記帳常常是在餐廳裡站著單手做的，而那正是這個 app 唯一的形態。

## 範圍

**要做的**

- `theme.dart` 的顏色 token 對齊網頁版，含 `muted` 的對比度修正
- 圓角六種收成四種
- 間距定成常數，把 6／10／14／18 這些不在網格上的值收掉
- 補上 `--text-card` 對應的那一級（20 與 14 之間現在是空的）
- 把對比度寫成測試 —— 這是無障礙缺陷，不該只靠人眼記得
- `expense_form_page.dart` 十一個欄位重分成三張卡
- 送出鈕固定在畫面底部
- 欄位順序對齊網頁版（分類排到名稱前面）

**明確不做的**

- **不做陰影四階與卡片三身分。** 網頁版的 `.card` / `.card.flat` / `.card.raised`
  在 Flutter 沒有等價物 —— `CardTheme` 現在是 `elevation: 0` 加一圈邊框，
  等於網頁版的 flat。要做三身分得先有一個 `AppCard` 抽象，那是獨立的一件事。
  **記錄，不做。** 這一輪的三張卡用現有的 `Card` 就夠：白底加淡邊框在米色背景上
  已經分得開。

- **不動字級的 26 與 16。** 網頁版是 30（`--text-title`）與 20（`--text-section`），
  但那是桌面 520px 容器裡的值。**顏色是身分與無障礙，必須一致；尺度是媒介差異，
  本來就該不同。** 只補中間缺的那一級，不去追平已經有人調過的兩個。

- **不改任何金額計算、分攤邏輯或送出流程。**

- **不重構 `place_field.dart` 與 `receipt_field.dart`。** 它們早就抽好了 ——
  這次網頁版才追上 Flutter，不是反過來。

- **不動 `src/`（網頁版）。**

- **不修 `dictation_service.dart` 的 deprecated 警告。** `flutter analyze` 現在有
  1 個 info，是既有的，跟這次無關。**它是基線，不是我們製造的。**

## 一、token

### 1.1 `muted` 的對比度（這是缺陷，不是偏好）

灰階整條往下移一階，跟網頁版同一個做法：不加新顏色，把每一階都調深，
階數與色相都不變。

| | 現在 | 改成 | 對 `bg` 的對比 |
|---|---|---|---|
| `muted` | `#8A8078` | `#6F665E` | 3.4:1 → **4.9:1** |
| `soft` | `#A39A90` | `#8A8078` | 2.4:1 → 3.4:1 |

`muted` 用了 21 處，加上 `textTheme.bodySmall` 這個**隱式**的使用者 ——
後者才是大宗。改一行修掉全 app。

`soft` 現在的使用次數是 **0**。它已經是死 token，但仍然照網頁版把值改掉：
下一個人用到它時，拿到的該是「過得了非文字 3:1、過不了文字 4.5:1」那一階，
而不是一個誰也過不了的舊值。

### 1.2 定義了卻從來沒用的三個

| token | 使用次數 |
|---|---|
| `primaryDark` | **0** |
| `soft` | **0** |
| `successSoft` | **0** |

`primaryDark` 這個最值得說：網頁版那一輪把**所有**橘色文字改成它，
理由是 `primary`（`#E8590C`）當文字只有 3.6:1。Flutter 把常數抄過來了，
卻沒有跟著做那次遷移。

好消息是 Flutter 這邊幾乎沒有把 `primary` 當文字色用的地方 ——
只有 `category_chart.dart` 與 `onboarding_page.dart` 兩處，而且都是色塊不是文字。
所以這一輪只要**確認**，不需要大規模遷移。

### 1.3 要補的顏色

網頁版有、Flutter 沒有的：

```
primaryDeep    #9A3412   primaryDark 升格成靜止色之後空出來的 hover／pressed
primaryB1/2/3  #E8590C / #F0A072 / #F7D3BD   佔比條的三階明度
track          #F0EBE4   頁籤與分段控制的底槽
dangerLine     #F3D2CE   危險區域的邊框
dangerSoft     #FFF5F5   危險區域的底
dangerQuiet    #B8837C   平時的刪除鈕。正紅留給按下去的那一刻
skeleton       #EFEAE3
skeletonHi     #F7F3EE
```

`danger` 現在用了 **45 次**，全部是同一個正紅 —— 邊框、底、文字、按鈕前景
都是它。網頁版已經拆成四階。這一輪**只補上常數，不做遷移**：
把 45 處分類是另一件事，而且大多數不在這次動的兩個檔案裡。**記錄，不做。**

補常數而不遷移看起來像做一半，但反過來更糟：需要 `dangerQuiet` 的人
發現它不存在，就會自己寫一個 `Color(0xFFB8837C)`，那才是真的回不去。

### 1.4 圓角四階

現在全 app 用了六種：

| 值 | 次數 |
|---|---|
| 12 | 8 |
| 20 | 3 |
| 16 | 3 |
| 999 | 2 |
| 22 | 1 |
| 10 | 1 |
| 4 | 1 |

網頁版收成 `sm 10 / md 14 / lg 18 / xl 22 / pill 999`。對應關係：

- `12` → `md 14`（最多的那一種）
- `16` → `md 14`（按鈕）
- `20` → `lg 18`（卡片）
- `22` → `xl 22`（不動）
- `10` → `sm 10`（不動）
- `4` → `sm 10`，除非它是某個特別小的東西 —— **實作時看一眼再決定**
- `999` → `pill`

### 1.5 間距常數

現在用到的值裡，`6`（14 次）、`10`（7 次）、`14`（4 次）、`18`（4 次）
不在 4px 網格上。網頁版的網格是 `4 / 8 / 12 / 16 / 24 / 32`，外加一個
`--space-text: 2px` 給「標籤在上、數值在下」那種行距微調。

定成 `AppSpace` 常數。**這一輪只定義、只在動到的檔案裡用**，
不去掃全 app 的 `SizedBox` —— 那是第三輪的事。

### 1.6 字級只補一級

```
titleSmall: 17px, w800   // 對應網頁版的 --text-card 與 .card-head
```

20 與 14 之間現在是空的，所以三張卡的小標只能在 `titleMedium`（16，跟內文差不多）
與 `headlineSmall`（26，太大）之間二選一。網頁版加 `--text-card` 就是為了這一格。

## 二、支出表單三張卡

### 2.1 分組

依「你會不會動它」分，不是依主題分 —— 跟網頁版同一條規則。

**卡 1（主卡，沒有小標）**

分類 chips · 支出名稱（含語音）· 金額 ＋ 幣別 · 匯率與換算後金額（跨幣別時）

它是主角，不需要一個標題來宣告自己是主角。兩個必填欄位都在這裡。

**卡 2「這趟的細節」**

日期與時間 · 地點 · 收據 · 備註

**卡 3「怎麼分」**

誰先付的 · 分攤方式 · 分攤成員／每人金額

### 2.2 欄位順序要改一處

Flutter 現在是**名稱在分類前面**，網頁版是**分類在前**。統一成網頁版的順序，
理由是網頁版註解裡那句：先按一下分類，名稱要打什麼通常也就想好了；
而且手指從分類滑到名稱是連續動作。

其餘順序兩邊本來就一致。

### 2.3 換算後金額併進匯率那一格

現在它是一個獨立的 `Padding`，浮在 `_Field` 外面。併成匯率欄位的 `hint`
或緊接的一行小字 —— 跟網頁版壓成 `≈ TWD 672` 一行是同一件事。

### 2.4 為什麼不是四張卡

依主題分（「這筆是什麼／多少錢／什麼時候在哪／怎麼分」）比較自明，
但要四張卡，而卡片的 padding 是有成本的 —— 總高度會比現在更長，
那是反方向。而且那樣會把「金額」推到第二張卡，那是兩個必填之一。

## 三、固定送出列

### 3.1 Flutter 這邊比網頁版簡單

網頁版為了這件事要處理 `position: sticky` 與 iOS Safari 虛擬鍵盤把 `fixed`
元素頂歪的問題。Flutter 沒有這個問題：

**`Scaffold.bottomNavigationBar` 加上預設的 `resizeToAvoidBottomInset: true`，
鍵盤跳出來時 body 會縮、那一列會被推到鍵盤正上方。** 這是框架直接管理
view insets，不是靠 CSS 猜。

所以這一項在 Flutter 是**用對元件**，不是 workaround。要包 `SafeArea`
（iPhone 底部那條橫槓），並給它一個**白色**背景 —— 預設是透明的，
下面的欄位會直接穿過去。

**背景是 `card` 不是 `bg`，這一條是對比度測試逼出來的**：錯誤訊息印在
這一列上，而 `danger` 對頁面底色只有 4.10:1、對白底才有 4.66:1。
見 §4.1。

### 3.2 進固定列的只有送出鈕與錯誤訊息

錯誤必須跟著進去。送出失敗時 `_error` 會被設值，如果它印在捲動流底部
而使用者停在上面，他會按了送出、什麼都沒發生、也不知道為什麼。

### 3.3 刪除留在捲動流裡

**這條不能妥協。** 網頁版的 `93be088`（*Stop putting the destructive button
under the thumb*）講的就是手機：系統對話框「OK 落在哪不是我們能決定的，
而它傾向落在拇指下」。固定在螢幕底部的那一列就是拇指的定位點。

附加好處：刪除需要刻意捲下去才找得到 —— 那正是它應得的摩擦。

Flutter 這邊沒有「取消」鈕（AppBar 的返回鍵就是），所以固定列外只剩刪除。

### 3.4 捲動區底部要留白

`SingleChildScrollView` 現在的 padding 是 `fromLTRB(16, 8, 16, 32)`。
底部那個 32 要留著或加大，否則最後一個欄位會被固定列蓋住。

## 四、可測的部分

跟前幾輪一樣，版面測不到。但**這一輪有一件網頁版沒做到的事**：

**對比度可以寫成測試。**

`muted` 對 `bg` 是 4.9:1 這件事，現在只存在於註解裡 —— 而註解不會在有人
把顏色調亮一點的時候變紅。WCAG 的相對亮度公式是純函式，Dart 寫得出來，
`flutter test` 跑得到。

`test/theme_contrast_test.dart`（新增）：

```dart
/// WCAG 2.1 的相對亮度與對比度。公式不長，而「這個灰在這個底色上讀不讀得到」
/// 是一個有標準答案的問題 —— 那種問題該讓測試回答，不是讓下一個人用眼睛猜。
double contrastRatio(Color a, Color b);
```

要斷言的：

- `muted` 對 `bg` ≥ 4.5:1 —— 它是內文的顏色（`bodySmall` 的預設）
- `ink` 對 `bg` ≥ 4.5:1
- `ink` 對 `card` ≥ 4.5:1
- `primaryDark` 白字在上 ≥ 4.5:1 —— 它是按鈕底
- `danger` 對 `bg` ≥ 4.5:1 —— 錯誤訊息是文字
- `soft` 對 `bg` ≥ 3:1 —— 它只用在非文字，門檻是 3:1；**同時斷言它
  「過不了 4.5」**，這樣有人拿它去印文字時，測試會擋下來

最後那一條是重點：它把「這個顏色不是給文字用的」從註解變成了機器讀得懂的規則。

### 4.1 這個測試寫出來的第一天就抓到一個沒料到的

原本這一節列的斷言裡有一條是「`danger` 對 `bg` ≥ 4.5:1 —— 錯誤訊息是文字」。
**它紅了：實際是 4.10:1。**

| `danger` `#D63939` | |
|---|---|
| 對 `card`（純白） | **4.66** ✓ |
| 對 `surface` | 4.47 ✗ |
| 對 `bg` | **4.10** ✗ |

網頁版用的是同一個值，所以那邊也一樣 —— 這不是 Flutter 落後，是兩邊共有的。

**處理方式：斷言改成只守白底，並把「錯誤文字只能放在白底上」寫成規則。**
這直接決定了 §3.1 固定送出列的背景要用 `card` 不用 `bg`。

**不順手把紅色調深**（`#C92A2A` 對 `bg` 是 4.79:1）：那要同時改網頁版才
保持得住「兩邊是同一個產品」，範圍超出這一輪。**記錄，不做。**

## 六、環境與基線

- Flutter **3.47.1**，SDK 在 `C:\dev\flutter`（**不在 PATH 上**，
  每次都要先 `$env:PATH = "C:\dev\flutter\bin;$env:PATH"`）
- `flutter test` 基線：**380 passed**
- `flutter analyze` 基線：**1 issue**（`dictation_service.dart:97` 的

## 七、驗收

### 7.1 自動

- `flutter analyze` 仍然是 1 issue，沒有新增
- `flutter test` 通過，數字是 380 + 新增的對比度案例
- **對比度測試確實會失敗於錯誤的顏色**：把 `muted` 改回 `#8A8078`，
  那一條要紅；改回來再確認綠

### 7.2 掃描

- `theme.dart` 裡搜不到 `0xFF8A8078` 當作 `muted` 的值
- `expense_form_page.dart` 裡有三個 `Card`
- `expense_form_page.dart` 裡搜不到 `circular(12)` 與 `circular(20)`

### 7.3 人工（在模擬器或實機上）

- 新增一筆支出：只打名稱與金額，**不捲動**就按得到送出
- **叫出鍵盤時送出列被推到鍵盤正上方**，沒有被蓋住、也沒有消失
- 最後一個欄位不會被固定列蓋住
- 編輯一筆支出：**刪除鈕要捲到底才看得到**，不在固定列裡
- 送出失敗時錯誤出現在固定列裡
- 次要文字（日期、成員數、提示）明顯比之前清楚
- 跨幣別時匯率在卡 1，換算後金額緊跟在它下面
- 分類在名稱上面
