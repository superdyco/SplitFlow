怎麼進去，以及動手時會怎樣

這一頁不是後台的頁面，是後台的兩條邊界：誰進得來，還有唯二會動到別人東西的對話框長什麼樣

管理者身分不在資料庫裡，在 token 上

1 用指令授予

在本機跑 npm run set-admin -- <email>，用 Admin SDK 寫下 custom claim。沒有「在網頁上把自己升成管理者」這條路。

2 後端每次都自己查

後台的資料一律走 callable functions，每支進來先驗 token.admin === true。Firestore 規則完全不用為管理者開洞，users 仍然只有本人讀得到。

3 只有網頁版有這段路由

Flutter App 沒有 /admin，也沒有呼叫這些 function 的程式碼。手機上不存在這個後台。

不是管理者的人打開 /admin

找不到這個頁面

網址可能打錯了，或這個頁面已經不在了。

回 404 不回「權限不足」是故意的：後者等於告訴對方這個網址是真的、只是他不夠格。這次嘗試仍然會進稽核日誌。

撤下公開報告

撤下「曼谷五日的旅費報告」

連結會立刻失效，也會從探索頁移除。任務本身、支出與分攤都不動。

撤下理由（必填，會寫進日誌並通知發布者）
報告內含他人的個人資料
補充說明（選填）
寫給發布者看的一兩句話

他可以修好之後自己重新分享，這不是永久封鎖。強制封存任務用同一個版型。

停用帳號

停用「winnerbot」的帳號

他將無法再登入。已經記過的支出、分攤與付款全部留在任務裡，其他成員的帳不受影響。

不是立刻生效，最長還有 1 小時

停用擋的是換發新憑證。他手上那張最長還能用 1 小時，這段時間仍然讀得到、也寫得進他已加入的任務。這是 Firebase 換發 token 的機制，關不掉。真的緊急就先撤下他的公開報告、封存出問題的任務。

停用理由（必填，會寫進日誌並通知本人）
大量建立空任務

那塊紅框不是提示，是規格的一部分。這個限制寫在文件裡會被忘掉，寫在這裡每次動手都會看到一次。

後台做不到的事

不能讀單筆支出的名稱、地點、備註與收據照片；不能替使用者新增或修改支出；不能加入任務或改成員角色；不能改任何人的暱稱；不能刪除帳號或任務。真的需要動資料的時候，走的是 Firebase Console 加上一筆手寫紀錄，而不是在這裡多開一個按鈕。
